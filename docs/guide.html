Integration Guide

How to report sales to the Sandbox Partner Platform so every partner gets credit for the shoppers they send. Written for the developer setting it up. The platform and the store in the examples are fictional.

1. How tracking works

  1. A shopper clicks a partner's link. The platform records the click and sends the shopper to your site with ?clickid=clk_… added to the address.
  2. Your site saves that click ID.
  3. When the shopper buys, your site or server sends the order to the platform with the click ID.
  4. The platform credits the partner. If the order is refunded, you report that too, and the commission is taken back.

2. Capture the click

Read clickid on the first page the shopper lands on and save it in a first-party cookie for 30 days. Do this before any redirect.

const clickId = new URLSearchParams(location.search).get("clickid");
if (clickId) {
  document.cookie = `partner_click=${clickId}; max-age=${30 * 86400}; path=/; SameSite=Lax`;
}
Most common problem: a redirect (to a mobile page, a country site or a new checkout domain) drops the clickid parameter. Keep it on every redirect, or save it before redirecting.

Pass the click ID through unchanged. Don't trim, re-encode or lowercase it. It always looks like clk_ followed by 10 letters or digits.

Using both is fine. Send the same order_id from each, and the platform counts the sale once.

4. Server to server

POST /v1/conversions
Authorization: Bearer <your live key>
Content-Type: application/json

{
  "click_id": "clk_ab12cd34ef",
  "order_id": "JS-10421",
  "amount": 84.50,
  "currency": "USD"
}

A new sale returns 201 with "status": "approved". Sending the same order again returns 200 with "status": "duplicate", and it isn't counted twice. Problems return a clear error code.

5. Browser tag

Place this on the order confirmation page, and fire it once per order:

<img src="https://platform.example/v1/tag.gif?click_id=CLICK_ID&order_id=ORDER_ID&amount=84.50&currency=USD"
     width="1" height="1" alt="">

The tag always returns an image, even on error, so it never breaks your page. To debug, check the X-Conversion-Result response header in your browser's network tab.

7. Authentication

Server calls need Authorization: Bearer <key>. Use the test key while building and the live key in production. Sales sent with the test key are recorded as tests and never pay commission. The browser tag needs no key.

8. Refunds

When an order is fully or partly refunded, tell the platform so the commission is adjusted:

POST /v1/conversions/JS-10421/reversal
Authorization: Bearer <your live key>

{"amount": 42.25}

Leave out amount to reverse the whole order. The best place for this call is wherever your system already processes refunds.

9. Lookback window

A sale is credited only if it happens within 30 days of the click. Later sales return click_expired. That's expected behavior, not an error in your integration. The window can be changed in the program settings.

10. Testing and going live

  • Click a test partner link and confirm clickid is still in the address after every redirect, on desktop and mobile.
  • Place a test order with the test key and confirm it returns 201.
  • Check that the amount matches the order exactly, in the main currency unit.
  • Place an order in each store currency and confirm the currency is correct.
  • Reload the confirmation page and confirm the second report comes back as duplicate.
  • Refund a test order and confirm the status changes to reversed.
  • Switch to the live key and stop reporting orders marked as tests.
  • After a week live, run the health check to compare your orders with what the platform received.
